## Real llmster CLI Evidence

Checked directly against an installed llmster build (CLI commit `71bd99c`) on the development machine, not only documentation — see `openspec/changes/llmster-lifecycle/design.md`'s "Real CLI behavior" section for the full account:

- Confirmed exact subcommand/flag syntax for `daemon up|down|status` and `server start|stop|status` via `--help`, matching the design.
- `lms daemon up --json` on this machine (LM Studio.app never launched) fails to wake the daemon: prints plain-text errors, no JSON, and **exits 0** after roughly 60 seconds. This is environmental (llmster's headless wake path most likely needs the GUI app's first-run registration), not a Lattice defect, and is exactly why the design never trusts that command's exit code.
- What this failure path proves about Lattice's own behavior: `start_model_runtime` against the real binary returns a `Failed`/`TimedOut` outcome without panicking; an immediately following `lms daemon status --json` reports clean `{"status":"not-running"}`; `ps aux` shows no orphaned process. The no-orphan guarantee holds under a genuine real-world CLI failure, not only under disposable fixtures.
