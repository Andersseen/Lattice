## Real Findings From Implementation (Not Assumed From Documentation)

- Confirmed directly in `Cargo.lock` (not merely asserted from `ureq`'s docs): `ureq = { version = "3.4.0", default-features = false }` resolves to patch `3.4.1` and adds zero `rustls`/`native-tls` dependencies — only `httparse`, `http`, `base64`, `ureq-proto`, `utf8-zero`, `libc`, `log`.
- Confirmed by reading `ureq` 3.4.1's own source (not its docs alone): `ConfigBuilder::timeout_recv_body` is a total body-read budget, not an idle/per-read timeout. This directly drove the reader/orchestrator two-thread design recorded in ADR 0012 and design.md — a single-thread design relying on that timeout alone would only cancel promptly by coincidence.
- A disposable loopback-fixture test reproduced a real `ureq` 3.4.1 timing edge case: a multi-write SSE response whose connection closes with zero delay after the last write can lose that final chunk in `ureq`'s `CloseDelimited` body reader. Reproduced first, then fixed only in the test fixture (a small trailing delay before closing, matching realistic server timing) with no change to `stream_completion`'s own parsing, which was independently verified correct beforehand. Recorded as an open item to re-check against a real llmster response (see "Pending Evidence").
- `serde`'s `#[serde(rename_all = "camelCase")]` on an internally-tagged enum (`#[serde(tag = "kind", rename_all = "camelCase")]`) only renames the tag's variant names, not each struct variant's own field names — `rename_all_fields = "camelCase"` is a separate, additionally-required attribute. Caught by a dedicated wire-shape test (`chat_stream_event_serializes_with_camel_case_kind_tag`) before the mismatch ever reached the hand-written TypeScript bindings.
