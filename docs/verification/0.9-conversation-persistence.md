## Design Decisions Confirmed By Implementation

- `ConversationStore` is a second, independent `rusqlite::Connection` to the same `lattice.sqlite3` file `SettingsStore` already owns, not a second file. `PRAGMA busy_timeout = 5000` and `PRAGMA foreign_keys = ON` were added to `database::open_connection`/`apply_connection_pragmas` and are applied to every connection, in-memory test fixtures included. `ON DELETE CASCADE` on `messages.conversation_id` was confirmed to actually fire in `deleting_a_conversation_removes_its_messages` and the e2e delete journey — it would silently not cascade without the `foreign_keys` pragma, since SQLite defaults it off.
- `start_chat_stream`'s request/response wire shape was amended in place (`StartChatStreamRequest`, `ChatRunHandle.conversationId`) rather than via a new `MODIFIED` delta, since `chat-streaming` has no permanent spec yet for OpenSpec's validator to diff against (confirmed the same way 0.7/0.8 established this precedent). The neutral `ChatRequest`/`ChatStreamEvent`/`run_chat_stream`/local adapter from 0.8 were not touched — confirmed by `providers::completion`'s and `providers::local_openai`'s full pre-existing test suites passing unchanged.
- The client (Angular `ChatStore`) remains the source of the transcript sent to the provider on every call, exactly as 0.8 shipped it; Rust only persists the trailing messages beyond what is already stored for a given `conversationId`. This kept the change to `providers::completion` at zero lines.
